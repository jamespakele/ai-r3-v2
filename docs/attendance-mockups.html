Approach 1

Daily Check-in Roster

The simplest possible thing: pick a date + location, see your participant roster, check the box. Built for speed at the outreach table.

Core idea: Attendance lives on its own tab ("Attendance" in the topbar). No "events" concept at all — just date + site + participant. This is the most direct implementation of the coordinator's statement: "It's a daily thing each location."

✓ Strengths

  • Fastest data entry — 3 taps to mark someone present
  • Zero learning curve; looks like a paper sign-in sheet
  • No new "events" concept to explain to volunteers
  • Works on phone at the outreach table
  • Minimal DB change — one new collection

✗ Trade-offs

  • No multi-day overview — you see one day at a time
  • Reporting requires export or a separate summary view
  • Doesn't group days into program "cycles"
  • Can't see attendance patterns at a glance

Approach 2

Calendar Matrix — Attendance Overview

A spreadsheet-style grid: participants as rows, dates as columns. See who's been showing up, who's stopped coming, and patterns over weeks — all on one screen.

Core idea: Same attendance collection as Approach 1, but the primary UI is a matrix grid instead of a daily roster. You can see the full "event" (multi-week program) at a glance. Click any cell to toggle present/absent. The calendar strip on top lets you jump to any date range.

✓ Strengths

  • Visual overview — immediately see attendance patterns
  • Spot dropouts (someone who stopped coming)
  • Great for reporting to funders/board
  • Can export as CSV for grants
  • Multi-week view matches "events last weeks"

✗ Trade-offs

  • More complex UI than a simple checklist
  • Can get wide with many dates (scrolls horizontally)
  • Not as fast for quick daily check-in
  • Better as a secondary "overview" view alongside Approach 1

Approach 3

Event Sessions — Programs with Daily Check-in

Introduces an "events" concept (multi-week programs like "R3 Summer Outreach 2026"). Each event spans many days at a location. Within an event, you check daily attendance. This matches the coordinator's suggestion: "maybe we should be tracking events."

Core idea: Admin creates an event (e.g., "R3 Waiʻanae Outreach — Aug 2026", start date, end date, site). The Attendance tab then shows a dropdown of active events. Select an event → see today's roster for that event → check people in. You can also see the full event's attendance history. This adds two new collections: events and attendance (now linked to events).

✓ Strengths

  • Matches how the coordinator already thinks ("events")
  • Events provide natural reporting periods for funders
  • Can have overlapping events at different sites
  • Enrollment: mark who's "expected" at an event vs walk-ins
  • Future-proof: events can have sub-activities (meals, court help)

✗ Trade-offs

  • More complex — admin must create events before tracking
  • Two new collections instead of one
  • Extra step: select event → then check in (one more tap)
  • Might be over-engineered if they just want simple daily counts
